## Packaging and runtime requirements

The public package supplies a **Windows 10/11 x64** unsigned Setup EXE and its documentation/notices. Users do not need Python. The builder integrates with locally owned Most Wanted (2005) or Carbon (2006) games and a compatible **existing ASI loader**. It does not silently replace unknown proxy/loader files.

**Public ZIP contents:** Setup EXE, `READ-ME-FIRST.txt`, `READ-ME-FIRST.html`, `CHANGELOG.md`, and `Third-party notices/`. **It does not contain application screenshots or the editable development source.** GitHub's autogenerated source archives are also documentation snapshots, not executable installers.

Beta 1.6 Public ZIP (107210753 bytes) and its Setup EXE (107119133 bytes) passed ZIP verification and exact SHA-256 calculation. See [checksums](SHA256-OF-BETA-1.6.txt). The Developer ZIP records successful clean Windows Setup install, installed-app smoke, documentation and uninstall verification.

## Most Wanted runtime

**Ordinary song routing:** Safe House/menu, Free Roam, Race, Pursuit and Shared. Configurable fade-in/out and finish-current-song switching apply to song playlists; independent music mix defaults to 65%.

**Original adaptive pursuit:** native in-game XNFSMusicPlayer installer extracts from the player's original game audio, displaying progress. The Windows builder arms/installs that feature but does **not** independently perform native extraction. The adaptive original score is not **T**-skippable.

**Custom interactive:** library-based song/node playback is separate from original mode. Three intended songs, T skip, EA Trax titles and original-mode pursuit exit fades were accepted in reported game sessions. Custom latest exit fade and full save-switch priming require additional tests.

**Modified executable support:** install compatibility requires all **61 checked native music-hook signatures** to match. Stock, modified and conflicting-hook fixtures were tested; this does **not** prove PLAK or all modified executables work in-game.

## Carbon runtime

Carbon player's Menu/Muscle/Tuner/Exotic/Shared masks and matched 1.2/1.4 payloads passed isolated tests; earlier actual **1.2** class routing, F9 and crew ducking were heard. 1.4 game behavior and original Canyon/Pursuit/Drift events remain unverified. There are **no independent custom Canyon/Pursuit pools** in this runtime. The Load Complete crash remains unresolved with no known confirmed cause.

## Music leveling and support

FFmpeg loudness processing creates separate playback copies at chosen target/peak settings, retains originals, validates outputs and caches accepted results. In-game radio/police/engine mixing remains distinct from audio-file normalization.

The Beta 1.6 **Support** window displays previews of a plain-English report and JSON and exports both in a single ZIP. The support ZIP excludes raw logs, private paths, song titles, music and saves. It is not sent automatically.

## Test interpretation

The handoff reports **10 disposable installation cycles**, **17 core regressions**, native transition tests, clean Windows installer lifecycle and packaged UI/payload checks. These are not equivalent to launching both games ten times or verifying Carbon 1.4. Reported Most Wanted session observations are described separately in [the acceptance table](WHATS-NEW-BETA-1.6.md).
